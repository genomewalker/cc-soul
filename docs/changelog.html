Changelog

Track the evolution of cc-soul. New features, improvements, and breaking changes across versions.

v5.21.0–5.21.56 May 2026 Latest

Added

  • Symbol-keyed event log (v5.21.56) — typed, WAL-backed event log keyed on symbol identity. SymbolEventLog organ stores Edited/Created/Deleted/TestFailed/TestPassed/Committed events with symbol_name, file_path, session_id, harness, and optional memory_id link. Indexed by symbol name and file path for O(1) lookup. upsert_symbol() C++ wrapper auto-logs an Edited event on every symbol write. invalidated_by field on MemoryState carries the commit hash or symbol-change ID that made the memory stale — set via mark_memory_invalidated. New MCP tools: symbol_event_log (query timeline), mark_memory_invalidated. FFI: cf_log_symbol_event, cf_query_symbol_events, cf_mark_memory_invalidated. WAL op: OP_SYMBOL_EVENT=67.
  • Write-gate (staged admission) (v5.21.55) — all new memories start staged=true and are promoted to staged=false on first recall (access_count ≥ 1). Staged memories score 0.80× lower in the retrieval pipeline (StagedFactor) so they surface only when no promoted memory wins. Stale staged memories (age > 7 days, never recalled) are auto-pruned. Background promotion pass runs every 50 embed cycles (~25 min) via promote_staged_memories(). New MCP tool write_gate_stats reports staged_count and oldest_staged_age_days. FFI: cf_promote_staged_memories (→ packed u64 promoted | pruned), cf_write_gate_stats (→ JSON).
  • Payload content sidecar (v5.21.50) — MemoryPayload.content moved from bincode into a flat .pld sidecar: [PLD_MAGIC:u64][count:u64]([id:u64][len:u32][bytes×len])×N. save_full_snapshot() writes .pld then clears content before bincode serialization; load_payload_sidecar() repopulates on load. v10 snapshots (content in bincode, no .pld) load transparently as a legacy path. New snapshot magic v1.0.11 (0xF011_5741_7E00_000B). At 1M memories × ~500 B average content: ~400 MB off the main bincode snapshot.
  • Flat binary scan Vec (v5.21.47) — hamming_candidates() now iterates a contiguous Vec<(MemoryId, [u64;4])> instead of HashMap::iter(). Position index (binary_vec_pos) gives O(1) swap-remove on delete; in-place update on upsert. ~4× fewer cache misses at 1M memories. Guard requires binary_vec.len() == binary_codes.len() before using the fast path.
  • Auto WAL compaction (v5.21.47) — maybe_compact_wal(threshold) checks segment count via wal_segment_count() and, if over threshold and 1 h has elapsed since last compact, calls compact_wal(). Called every 10 embed cycles (~5 min) from embed_loop with threshold=50. Cooldown tracked via last_compact_ms: Arc<AtomicI64> on ChittaField. FFI: cf_wal_segment_count, cf_maybe_compact_wal.
  • Episode TTL pruning (v5.21.47) — prune_episodes(max_age_days, max_count) deletes episodes older than 90 days with strength < 0.3, then caps total episode count at 10 K (80% target on cap trigger). Called every 200 embed cycles (~1.7 h). Exposed as prune_episodes MCP tool. FFI: cf_prune_episodes.
  • Mmap embedding skeleton (v5.21.47) — activate_mmap_embeddings() on SemanticIndex opens the .emb sidecar as a memory-mapped file (Arc<Mmap> to preserve Clone), builds a byte-offset index, and clears the heap HashMap. get_embedding() checks the offset index first. Guarded at >200 K in this release; completed in v5.21.48.
  • Mmap embeddings — fully active (v5.21.48) — EmbLookup<'a> struct introduced: holds shared references to heap: &HashMap, offsets: &HashMap<MemoryId, u64>, and mmap: &Option<Arc<Mmap>>. Rust field-level split borrows allow HnswGraph::insert, search, search_layer, and select_neighbors to use mmap-backed neighbor lookups while mutating the graph. total_embedding_count() unifies heap + mmap counts; used by use_hnsw(), use_tier2(), the Hamming guard, normalize_all() consistency checks, len(), is_empty(), and all_ids(). activate_mmap_embeddings() now fires whenever the .emb sidecar exists — no size threshold. backfill_hnsw_delta, merge_delta_into_base, and rebuild_hnsw all iterate both embedding sources. Heap freed at any scale after first checkpoint.
  • v10 snapshot format — embeddings stored in a .emb sidecar (magic header + count + flat {id, f32×256} records); binary sparse codes stored in a .bin sidecar ({id, u64×4}). Reduces main bincode snapshot size and structures both sidecars for future mmap-based loading at 1M-memory scale.
  • Two-tier HNSW — delta_hnsw activates above 100 K memories (HNSW_TIER2_THRESHOLD). New inserts route to a small delta graph (O(log Ndelta)) instead of the large base. Delta is merged into the base at checkpoint when it exceeds 10% of base size (HNSW_DELTA_MERGE_RATIO). Persisted as a .delta.hnsw sidecar alongside the base .hnsw. Search queries both tiers and fuses results via reciprocal rank fusion.
  • SSL NL gloss — gloss_ssl_content() in chitta/include/chitta/ssl_gloss.hpp translates SSL triplets (subject/predicate/object) into readable English sentences before embedding. Closes the representation gap between compact SSL format and BGE queries; SSL memories re-embedded via a one-time migration.
  • Alias memories — when a new SSL memory is stored, a linked kind=alias NL counterpart is auto-created and connected via an alias-of triplet. Keeps NL and SSL representations synchronised without duplicating content.
  • Embed worker fix — idle gate removed; the background embed worker now runs every 30 s during active sessions instead of waiting for an explicit activity signal. Pending queue clears even when the user is actively typing.
  • pending_embed_ids MCP tool — new maintenance RPC to inspect or purge the stuck embed queue. Supports purge_orphans (drop entries whose memory no longer exists) and force_clear (forcibly clear a given set of IDs).

Fixed

  • Compiler warnings (v5.21.54) — removed unreachable default_lsh_buckets() function (lsh_buckets is #[serde(skip)]); removed redundant top-level SessionRecallHit import in store.rs (re-imported locally inside the function); silenced #[allow(dead_code)] on InterventionStore::config field (reserved for future stale-threshold logic). Build is now warning-free.
  • HNSW sidecar staleness check (v5.21.53) — load_hnsw() validated the sidecar node count against self.embeddings.len() (heap only); with mmap active and heap cleared that would always be 0, causing any loaded sidecar to be rejected as “larger than snapshot.” Now uses total_embedding_count() (heap + mmap offsets).
  • Deleted set trimming (v5.21.52) — trim_deleted() on SemanticIndex retains only IDs still present as nodes in hnsw or delta_hnsw — the only structures that can surface a deleted ID in search results. Called at the end of every normalize_all() (once per WAL replay / restart); follows with shrink_to_fit() to return freed memory to the allocator. Prevents unbounded growth of the soft-delete set under high churn.
  • binary_vec delete path (v5.21.51) — SemanticIndex::remove() now clears emb_offsets for the removed ID; previously mmap-sourced memories leaked into total_embedding_count() and all_ids() after deletion, inflating the binary guard threshold and including deleted IDs in HNSW rebuilds. purge_wrong_dim() now explicitly clears binary_vec and binary_vec_pos alongside binary_codes rather than relying on the normalize_all() length-mismatch rebuild.
  • Mmap checkpoint data loss (v5.21.49) — save_embeddings_sidecar() previously wrote only the heap delta when mmap was active, overwriting the sidecar with a fraction of the dataset. Now copies raw f32 bytes directly from the mmap (zero-deserialise) and appends the heap delta; the next load and activate_mmap_embeddings() call recover the full combined dataset.
  • Binary codes wipeout after mmap activation (v5.21.49) — normalize_all() rebuilt binary_codes by iterating self.embeddings (heap-only), producing an empty map when mmap was active and disabling the Hamming fast path. Now iterates all IDs via EmbLookup over both heap and mmap.
  • provenance --cmd destination collision (v5.21.24).
  • Pre-tool-hook exec bit restored after release tarball.

v5.14.0 April 11, 2026

Added

  • Surprise Memory (Layer 4) — Prediction error tuples that reveal blind spots. Record what was expected vs what actually happened; query recurring surprise patterns; identify domains where predictions consistently fail. SurpriseDomainFactor in scoring pipeline boosts “actual” outcomes and suppresses wrong “expected” predictions. Friston (2010).
  • Epistemic Debt (Layer 5) — Uncertainty boundaries and competing hypotheses. Register fragile beliefs with competing explanations and discriminating tests; resolve or defer debts as evidence accumulates. EpistemicDebtFactor boosts memories in uncertain domains. Sperber et al. (2010).
  • Integration Kernel (Layer 6) — Recall source arbitration with learned weights. Track which recall sources (semantic, keyword, temporal, artifact, association) are useful per domain; weights update via Bayesian feedback. IntegrationWeightFactor applies learned source weight as multiplier. Shazeer et al. (2017).
  • 14 new MCP tools — record_surprise, query_surprises, get_blind_spots, surprise_stats, register_debt, resolve_debt, defer_debt, query_debts, get_fragile_decisions, debt_stats, record_feedback, get_source_weights, update_source_weight, integration_stats.
  • 18-factor scoring pipeline — 3 new factors (SurpriseDomain, EpistemicDebt, IntegrationWeight) extend the pipeline from 15 to 18 composable factors. New config params in scoring.json.
  • 5 new WAL op codes — OP_RECORD_SURPRISE=39, OP_REGISTER_DEBT=40, OP_UPDATE_DEBT=41, OP_UPDATE_SOURCE_WEIGHT=42, OP_RECORD_FEEDBACK=43. All replay from WAL — no snapshot version bump needed.
v5.12.0–5.13.0 April 11, 2026
