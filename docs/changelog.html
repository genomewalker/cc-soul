Release History

Changelog

Track the evolution of cc-soul. New features, improvements, and breaking changes across versions.

v3.43.35 February 25, 2026 Latest

Added

  • Self-improvement loop (impl_start) — Dedicated tool that creates an impl sadhana with goal_dsl={"kind":"impl"}. Each daily cycle reads pending [impl] / [dream][impl] memories, implements the change in the repo, runs an opencode review gate, and commits only if approved
  • Architectural reflection in dreams — Dream system prompt now includes an ARCHITECTURAL REFLECTION step: before completing, the agent checks whether findings have direct implications for memory storage, retrieval, or reasoning, and stores them as [dream][impl] memories if so
  • goal_dsl parameter for sadhana_start — Optional JSON object that selects a typed system prompt in build_system_prompt(); kind:"dream" triggers the dream prompt, kind:"impl" triggers the impl prompt
  • REINFORCE-style credit attribution in ResonanceLearner — process_feedback() now scales each BetaPrior update by the sampled parameter’s deviation from its current mean, breaking the 7-prior convergence lockstep that caused uniform-reward degeneracy
v3.43.28–3.43.32 February 23–24, 2026

Added

  • dream_cancel and Oracle pattern — Cancel a dream and mark as forgotten; dream_wander now consults an opencode oracle to select the most productive topic from candidate gaps
  • dream_force_woke — Force a stuck or overlong dream to woke status, backfilling findings and memories_created from sadhana history
  • sadhana_stop / sadhana_pause in CLI — Both tools added to KNOWN_TOOLS so they’re callable from the command line
  • Max concurrent dreams raised to 10 — Up from 5; rate limit now enforces max 2 concurrent active dreams with 4–hour minimum interval

Fixed

  • dream_status now shows brain_provider and brain_model fields
  • Dream rollback on sadhana start failure cleans up orphaned dream records correctly
v3.43.6–3.43.27 February 21–23, 2026

Added

  • Full dream tool suite — dream_start, dream_wander, dream_list, dream_status added to CLI KNOWN_TOOLS and MCP surface
  • Convergence metrics (convergence_metrics) — Tracks triplet traversal depth and graph convergence across recall cycles
  • Resonance stats (resonance_stats) — Per-memory resonance history with decay curve visualization
  • Per-sadhana max_turns — Each sadhana can cap agent turns per cycle independently
  • Feedback loop improvements — Dream deduplication, correction memory decay, sadhana performance stats
  • Kriya skill (/kriya) — Review soul findings one by one, accept or discard, implement accepted ones, build and optionally release
  • Sadhana TUI redesign — Clickable event rows with inline expansion, animated terminal mockup, live JS effects
  • Cost tracking — cost_usd recorded per sadhana cycle

Fixed

  • HNSW index crash loop resolved — dropped experimental persistence, threads=1, added corruption recovery and synchronous rebuild at startup
  • Background hooks now close stdin and redirect stdout to /dev/null (prevented terminal input theft and new-folder freeze)
  • Ghost line problem — strip line numbers from code memories before storage
  • alarm(15) watchdog ensures daemon exits if threads hang on shutdown
  • Smart-install always fetches latest release from GitHub (was caching stale version)
  • All 6 daemon reliability bugs found and fixed by sadhana #21 investigation
v3.43.1–3.43.5 February 20–21, 2026

Added

  • Soul dreams — svapna (dream_start, dream_wander) — When the daemon is idle for >10 minutes, it picks a topic from memory gaps or curiosity seeds, web-searches it, and stores what it finds as [dream]-tagged memories. Dreams run as typed sadhanas with a dedicated exploration prompt
  • Real-time sadhana event streaming — Persistent socket connections stream live cycle events for monitoring sadhanas as they run
  • dream table in DuckDB — Stores dream records with topic, status (dreaming / woke / forgotten), findings, memories_created, and sadhana linkage

Fixed

  • Use --system-prompt flag for claude CLI (was --system, caused silent 365ms failures per cycle)
v3.42.16 February 20, 2026

Added

  • Soul Utility Score (SUS) — Five-dimensional metric system measuring soul effectiveness: R (relevance), P (recall precision), M (mistake prevention), T (cache efficiency), D (durability). Geometric mean formula with configurable weights. Available via chitta metrics CLI and get_sus_metrics MCP tool
  • Cache efficiency tracking (T metric) — Extracts cache hit ratios from transcript JSONL at session end; detects cache break patterns and surfaces them as correction memories
  • Correction outcome tracking (M metric) — Tracks whether exposed correction memories actually prevented errors; logs outcomes per session for precision scoring
  • Auto-distillation at session end — Stop hook triggers transcript distillation automatically without manual invocation
  • Implicit resonance feedback — Lexical overlap detection (≥50% key terms) between exposed memories and assistant response automatically strengthens relevant memories
  • Integer coercion for MCP tool args — LLMs sometimes serialize integer params as JSON strings; schema now accepts both and server coerces at dispatch

Fixed

  • Restored missing cc-soul-mcp skill (referenced in marketplace.json but absent from repo)
  • Input validation error: '19' is not of type integer — 100 integer schema params now accept string-typed values from LLM tool calls
